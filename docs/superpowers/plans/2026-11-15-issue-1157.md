# #1157 홈 에피소드 카드 중복 제거

## 설계와 범위

서로 다른 URL이라 기존 URL 중복 방지는 정상 통과한다. 공식 Rails 발표가 연결한 팟캐스트 에피소드와 영상만 명시적인 URL 목록으로 등록한다. 제목·요약·embedding 유사도는 근거로 사용하지 않는다. 자동 수집·DB 그룹 모델보다 확인된 네 사례를 등록하는 방식이 현재 범위에 적합하다.

홈의 주요/최신 뉴스 공통 scope에서 중복을 제외한 뒤 기존 개수·기간·정렬 규칙을 적용한다. 표시 가능한 글 중 가장 최근 수집된 글(created_at, id 내림차순)을 대표로 삼아, 오래된 발표가 새로 수집한 영상을 홈에서 밀어내지 않게 한다. 대표가 삭제·미확정·무관하면 다음 표시 가능한 글로 대체한다. url 또는 origin_url이 등록 URL과 정확히 일치해야 한다.

모든 홈 카드 크기에 같은 출처 링크 컴포넌트를 사용한다. 기존 Article·좋아요·댓글·요약·번역·slug는 수정하지 않는다. 검색·API·RSS·사이트맵은 기존 글을 유지한다.

## 검증 순서

1. PostgreSQL 전용 테스트 DB에서 기존 홈에 세 카드가 표시되는 회귀 테스트를 먼저 실패시킨다.
2. URL 목록, 함수 모듈, 홈 scope 적용, 공통 링크 컴포넌트와 ko/ja/en 번역을 구현한다.
3. 양 호스트, 주요/최신 뉴스, 대체 대표, origin_url, 정원 보충, 별개 방송(#555), 기존 글 접근을 검증한다.
4. RSpec → 전체 Minitest → bin/rake quality, RuboCop·Sorbet·Packwerk를 확인한다.
5. graphify update . 실행 후 변경 전후와 검증 결과를 커밋·Draft PR에 기록하고 #1157을 연결한다.

등록되지 않은 에피소드·URL 변형은 기존대로 표시한다. 추가 사례는 공식 출처의 링크 관계를 확인하고 목록에 추가해야 한다. 반복 등록 비용이 커지면 수집 시 공식 에피소드 식별자를 저장하는 구현을 검토한다. 실제 운영 데이터 수정·배포와 검색 색인 영향 측정은 범위에 포함하지 않는다.
