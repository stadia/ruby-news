# 기사 처리와 외부 전달 유스케이스

코드 분석을 바탕으로 작성했으며 사용자 검토와 승인을 거쳤다. 인스턴스 기반 서비스는 처리 순서·실패 전파·외부 전달 정책을 소유한다. 순수 계산과 영속 모델의 제약은 각각의 소유 경계에 둔다. 전체 연결은 `ruby-news-architecture`를 따른다.

## 기사 파이프라인

ArticleAgentsService는 본문 확보 → 임베딩 → 한국어 요약·메타데이터 → 윤문 → 썸네일 예약 → 일본어 번역 → 무관 기사 정리 순으로 동작한다. 보조 산출물 실패를 모두 기사 본문 실패와 동일하게 다루지 않는다.

본문 부재·너무 짧은 본문은 폐기할 수 있지만 일시적인 수집 실패·저장 실패·예외는 보존하고 실패를 반환한다. 저장에 실패해 메모리에 남은 변경이 후속 저장으로 섞여 들어가지 않도록 되돌린다. 윤문 실패는 상태에 남기되 이후 처리를 계속한다. 커밋 뒤 콜백 실패를 이미 저장된 윤문 자체의 실패로 덮어쓰지 않는다.

무관 기사 자동 폐기는 지정된 자동 수집 client에 한정하고 사용자 직접 등록을 보호한다. 폐기는 이후 산출물의 discarded 가드를 유발하므로 파이프라인 마지막에 한다. 재시도 가능 기간은 무한하지 않다.

## 전달

SocialMediaService 기반 플랫폼별 서비스 구조를 유지한다. 게시 적합성 검사와 플랫폼별 게시·삭제를 구분하고 기존 social_post_ids 계약을 보존한다. Slack·Discord 전달, Web Push, IndexNow 등도 이 경계의 유스케이스지만 전송 기록·자격증명·오류의 세부 계약은 각 구현과 테스트를 확인한다. 모든 외부 전달을 하나의 트랜잭션으로 보장하지 않는다.
